# 风格探索模式：先让用户挑真实案例，再决定穿搭

## 什么时候立刻进入
- 用户不喜欢此前推荐，说“太土”“太老气”“都是欧美”“你别乱想”“找穿搭库”“没有审美”“都不喜欢”。
- 用户尚未建立喜欢/讨厌风格清单，或者脸照无法确定衣品喜好。
- 用户想“看看不同风格”“找灵感”“有没有比传统轻熟更好看的”。

**此时停止强推“三套成品”，先真实参考校准。**

## 操作顺序
1. **承认失配但不要解释过多**：过去建议缺少真实案例支撑，不能只看脸就“诊断”喜欢哪种风格。
2. **找原始实例**：优先 P1 真人小红书/得物原帖；再 P2 品牌官网造型；如果实际工具不支持联网，就用已有核验过的种子库，标明核验日期，或请用户发喜欢的穿搭截图。
3. **展示 4–6 个多样化案例**（只有3个真的可验就只给3个）：每个给**原帖/原图入口**、来源类型、观察到的真实服装结构、与上一轮推荐有哪些本质差别。只看得到上半身则不臆测裤鞋。拒绝只给“轻熟商务/少年文艺”等抽象词。
4. **先请用户选喜欢/不喜欢，最好能指明喜欢某个局部**，例如“A的夹克+C的裤型，但不喜欢鞋”。必要时单次只问“这些案例里哪一套最接近你想要的方向？”。
5. **形成可重复使用的风格偏好摘要**：喜欢的廓形、颜色、松量、单品、发型、避免项；只在当前对话使用，未经明确授权不要写个人永久文件。
6. **再把风格用于本人**：根据用户的脸照与全身照（若有）调整上衣长度、裤脚、镜框附近的领口等，给三套不同场景的方案。明确哪些属于照片可见、哪些仅根据喜好或场景。
7. **来源回溯**：每套说明参考了哪个 ID/原始 URL，保留了什么、修改了什么。没有任何真实案例支撑不能自称“源自穿搭库”。
8. **反馈后复检**：用户否定某个参考，立即移出候选，不要改个颜色继续推相同版型。

## 候选卡片（普通文字即可）
**案例名 / 来源级别 / 原始网页 URL**
- 看得到：上衣（外层/内搭）、裤型、鞋型、关键色彩和比例；不可见即填“不详”。
- 风格差异：它与前一个案例的廓形/场景/材质不同在哪里？
- 可以借鉴：1–2 个实际细节。
- 注意：品牌大片/夸张松量/天气/照片角度对用户可能不适用。

**禁止**：杜撰达人账号、帖子浏览量、真人身高体重、以品牌页面充当“近似真人”照片、把已有照片未经授权发到网站做图搜、批量抓取有版权图进 ZIP。

## 选择后如何回应（不复读）
“你选了 **A 的短外套+ C 的直筒裤**，否定 B 的硬挺西装。结合你**已经提供的**身高 175 cm、体重 67 kg、正脸照，在没有全身照前，我能先帮你设计 A/C 风格方向，但衣长/裤长最终要试穿或补全身照；现在不会为了‘青年教师’硬推衬衫/西装。”

如果用户只想了解穿搭资源，不必进一步询问，也不强行做个人推荐。
