# 可检索穿搭案例库 · 工作流与判读规则（V2.3）

## 核心资产

- **`outfit-cases.json`**：本次整理的具体博主造型、明星媒体造型、官方 Lookbook 单品组及视频教程来源。
- **`curated-look-index.json`**：早期五条品牌种子/图库入口，仅作拓展参考，不要和新库记录混成“独立图片数量”。
- 所有照片仍在原作者/品牌网站上，**仓库不储存、镜像或再发布图片**。source_url 是页面入口，不是直接图片文件，也不能保证永远有效。
- 记录只有 verified_on=2026-11-04 的核验状态，**不等于实时图库**。网页失效须明确告知，不得伪称仍可访问。

## 五种证据类型与能做的事

| kind | 示例 | 可以引用 | 不得推断 |
|---|---|---|---|
| creator_outfit | 博主原帖中的 LOOK1/格纹案例 | 原帖描述的具体单品、搭配逻辑；按 source_segment 定位 | 未列出的裤子/鞋子、博主真实身材尺寸 |
| creator_video | 已验证视频标题 | 视频主题、作者、主张的方向 | 未看画面的完整穿搭和精确颜色 |
| celebrity_editorial | 井柏然媒体图文 | 报道已明确描述的造型与细节 | 所有照片都是本人日常私服或商品可购买 |
| brand_lookbook | UNIQLO:C 同一单品组 | 官方单品组合、版型方向 | 所有颜色、价格、库存以及用户适配 |
| curator_video | 博主合集 | 创作者发现入口、不同风格候选 | 视频说的博主都已逐一验证 |

confidence=high 是**原文/原始单品组的证据充分**，并非照片识别精度或用户个人适配分。confidence=medium 仅有部分已核实的单品。low 仅有主题/标题，**不能直接画成“完整真实 OOTD”**。

## 真实操作流程

1. **先区分用户现在的目标**：寻找风格 / 筛选局部 / 套装适配 / 购买；只有“购买”才查商品。用户不满意之前的推荐时，必须先找新的图片案例，而不是重绘旧的深棕套装。
2. **从新案例库筛来源**：只读 JSON 即可，按 styles/shapes/materials/colors/scenes 寻找。可选用随仓库提供的 `scripts/search_looks.py`（发布/维护才需要 Python；普通 Skill 使用不必执行脚本）。
3. **有网络能力时复核 source_url**：原页面仍存在、图片能看、来源类型与时段是否匹配；查到更多原帖后附来源。不能联网时只能称“截至 2026-11-04 已整理案例”，不说“刚刚看了最新”。
4. **反单一审美**：一次优先挑 4–6 个不同**服装结构**，同一创作者最多 2 个案例，不能 5 条全是同一个博主换颜色；优先原创中国博主，品牌/明星作为补充。源不足则如实少给。
5. **案例卡片结构**：原始 URL、作者/品牌、发布年、source_segment、证据类别、可见服装（未知部位填“未核实”）、值得学的组合方法、差异点。
6. **让用户按部位选择**：外套/内搭/裤型/鞋型/配色/发型分别选“喜欢/不喜欢/没感觉”，容许 A 上衣＋C 裤子＋B 配色；**不要要求整套二选一**。
7. **审美偏好是用户确认的，不是 AI 诊断**：喜欢的素材可以复用；不喜欢的直接排除。同一人偶尔喜欢复古格纹并不代表其他所有风格都不适合。
8. **最后再做本人适配**：根据用户已经提供的照片、尺码和场景说明可能改的衣长/裤长/领口/配饰；不能因用户自述肤色偏深而默认要求衣服深色或拒绝浅色。
9. **穿搭来源不可替代真人试穿**：同款在他人身上有型，不代表适合用户；本人换装图需宿主有可用图像编辑能力且用户明确要求。

## 离线检索示例（开发者可选）

```bash
python scripts/search_looks.py "格纹 松弛" --min-confidence medium
python scripts/search_looks.py "针织" --kind creator_outfit --limit 5
python scripts/search_looks.py "机能" --min-confidence low --json
```

默认过滤证据不足的低置信记录；可手动放宽为 low，但要严格说明信息仅来自视频标题/媒体主题。脚本不联网、不用 API、不读取照片、不储存用户资料，输出只是本地案例搜索结果。

## 案例收录与更新门槛

1. 只收真实存在、明确可追溯的 URL；不得用平台首页充当某位博主的具体 Look。
2. 必须标注 creator、kind、source_segment、verified_on、confidence、原帖发布日期（未知时 null）和证据局限。
3. pieces 仅填原始页面确实证实的衣物（不确定用 null）；不要将“作者推荐可搭配”写成“照片中已经穿着”。
4. 只保存原创的短摘要和用于检索的结构化标签，不保存原文长文或图像；引用原帖让用户自己查看。
5. 禁止把用户面容、身材私密参数或主观偏好写入公开数据库。
